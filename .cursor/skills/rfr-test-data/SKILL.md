# rfr-test-data v1

**Уникальность данных.** Username и прочие ключи — уникальны на каждый прогон (рандом/`RandomDataUtils`); не переиспользовать фиксированные логины между тестами.

**Владелец — дерево декораторов.** Ресурсы (auth/api-строки, партнёры, Friendship) принадлежат дереву `UserFixture` из `UserRequest.fixture()`; Store держит только корень и закрывает его. Каждый декоратор владеет своим origin и partners и чистит их в `TearDown`.

**Новое предусловие — новый декоратор.** Композиция в `UserRequest.fixture()`, без флагов в базовой фикстуре и без веток в `UserExtension`.

**SQL только в объектах строк `data/db`.** JDBC/SQL — в `Profile` / `Friendship` / `AuthAccount` и т.п.; не в `jupiter/`, не в `test/`, не в декораторах напрямую.

**Профиль API создаётся явно.** Api-профиль не «всплывает» сам: `ensureProfile` / `Profile.create` в декораторе или support, когда связь в api реально нужна.

**Пул заранее заведённых пользователей — только там, где создать нельзя.** Иначе всегда создавать и удалять через фикстуры; seed/пул — исключение для несоздаваемых сущностей.
